# Roadmap AION 7.7 PTS EU — что реально починить дальше

> 02.10.2026. Приоритезация по: влияние на геймплей × трудозатраты × риск.
> База: лог-скан VM 109 от 02.10.2026 + RaGEZONE 1211744 (#101–#204).

## Этап 0 — Сразу (без исследований) ⏳
1. **Перезагрузить VM 109** (ACP=28591 уже в реестре) → запустить `AION-START-SERVER.bat` (десктоп VM) → в RunAsDate нажать **RUN**. После ребута поднять LogServer64 (`schtasks /Run /TN AionLog`, задачи DISABLE — включить временно: `schtasks /Change /TN AionLog /ENABLE`). Гаснет лупер `Can't connect to log server` в CacheD.
2. **Рестарт Server64** — подхватит captcha 22206 (гаснет лупер Captcha −22206). Удобно совместить с ребутом из п.1.
3. Дождаться загрузки NPCSvr64 (~10–15 мин) и проверить в `MainServer\log\*.err`, что `NPCSvr hasn't connected` исчезло → **первый вход клиентом**: `bin64\aion.bin -ip:192.168.0.125 -port:2106 -cc:2 -noauthgg`.

## Этап 1 — Восстановление БД (главный рычаг) 🎯
Комплект «не полный» (papka #203): ~15% процедур отсутствует. Путь:
1. **Создать `aion_SetCharInfo_20160818`** — полная структура аргументов опубликована (klon22, RaGEZONE #110): 64 параметра с типами (`%d`=int, `%f`=real, `%u`=tinyint, `%I64d`=bigint, 2×nvarchar). Это чинит **сейв персонажа** (геймплей-блокер). Взять формат-строку из поста #110, сверить с логами вызовов CacheD (`{call aion_SetCharInfo_20160818(...)}` в `CacheServer\log\*.err`), собрать процедуру INSERT/UPDATE по таблице `user_data`.
2. **Собрать реестр недостающих процедур** парсером по логам: grep `{call aion_...` / `Could not find stored procedure` по всем `*.err` VM → таблица «процедура — кто зовёт — параметры». Скрипт: `scripts/log-scan.ps1` (расширить).
3. **Подтягивать из БД 5.8 PTS** (a7741200 #201: «5.8 databases are closer to 7.7») и из текстового дампа `Database\aionworld_110.bak` (там лежат тексты процедур — источник схем). Отсутствующие колонки в `user_data` сверять с `#110`.
4. Метод для «неизвестных» процедур: **заглушки** (принимают параметры, SET NOCOUNT ON, SELECT пустого резалтсета с правильным числом колонок/типов) — сервер перестанет сыпать ошибками, геймплей-фичи включаются по мере реальных реализаций. Проверено на `Log_TblGameServerInfo_UpdateServerstatus` (02.10).

## Этап 2 — Геймплейные баги (нужен IDA/Ghidra) 🔧
1. **Дома после lvl 9 / коллекции после 78 / дроп Heiron LF3** — патчи Server64 через Ghidra + PDB (`Server64.pdb` в ките!). Метод AKllX (#108): Ghidra → правка → recompile.
2. **Matchmaking (арены) на одном MainServer**: `IsEventServer=true` + JZ→JNZ (AKllX #108) — чтобы арены работали без отдельного сервера.
3. **Манастоуны-стекинг**: сравнить наш чистый Server64 с реверсом «фикса manastones» (TheReverend #106–111); делать свой патч на чистом exe (чужие ENIGMA-сборки не брать — риск бэкдора).
4. **Питомцы/свитки спрайтов** — сверить версию кита с «updated» a7741288 (март 2023); если наш кит старый — заменить Server64/скрипты из нового кита (без ENIGMA).

## Этап 3 — Операционная устойчивость ⚙️
1. **Ночной рестарт NPCSvr64** (утечка Abyss.cpp ~600k блоков/сессию): создать daily-задачу 05:00 `stop NPCSvr64 → start` (Server64 переживает отвал NPCSvr — reconnect по готовности).
2. **Watchdog-скрипт**: раз в 10 мин проверять процессы (AccountCache/L2Authd/AuthGateD/CacheD/ICServer/CAPTCHA/NPCSvr/Server64) и поднимать упавшие (PowerShell, в `scripts/`).
3. **Петишн (2107) / shop agent (10100) / ChannelChat (10254)**: сервисов в ките нет. Варианты: (a) игнор — некритично, лупер раз в ~10 с; (b) сниффер/дизасм Server64 → найти флаги отключения retry (`useCaptcha=false`-аналоги); (c) написать мини-эмуляторы на TCP-ответах протокола (низкий приоритет).
4. **NPRelayServer/RankingServer**: сгенерить config.xml (рецепт из постов #113/116 — country code, Data Center) — низкий приоритет.
5. **Веб-магазин** (Jagger1998 #36): опробовать web shop из 4.6 — гипотеза совместимости.

2. GM-инструменты: `tool\gmdb\gm.exe` + `tool\worlds\worlds.exe` (предустановлены) — заливка итестов контента.
