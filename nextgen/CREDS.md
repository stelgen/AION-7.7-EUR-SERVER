# 🔑 CREDS — политика кредов и доступов

> Решение юзера 08.10: креды (форумы, ssh, SQL и пр.) держать В ОДНОЙ ПАПКЕ на VM, чтобы любой агент/чат брал оттуда.
> **В гит/память/чаты/логи секреты НЕ класть** — здесь только политика и УКАЗАТЕЛИ на места.

## 1. ЕДИНСТВЕННОЕ МЕСТО — на VM

```
\\ VM 192.168.0.125 → D:\SAION\creds\
├── CREDS.md            ← мастер-файл: все доступы одним списком
├── rz-cookies.txt      ← cookies-сессия forum.ragezone.com (curl-файл)
└── ssh-agent-key.note  ← где приватный ключ (локальный путь), fp
```

**Правило для агентов:** доступы БРАТЬ из `D:\SAION\creds\CREDS.md` (читается по ssh), НЕ запрашивать повторно в чатах, НЕ копировать в гит/память. Если креда появилась впервые — добавить её ТУДА и сообщить юзеру, что она легла в одно место.

## 3. ПРАВИЛА СЕКРЕТОВ (не забыть)

1. Пароли/connStr/токены — ТОЛЬКО на VM (конфиги сервисов `D:\SAION\<svc>\config.yaml`, creds-папка). В гит — `config.example.yaml` с плейсхолдерами.
2. В память/чаты — только указатели («см. D:\SAION\creds»), не значения.
3. В логах — маскирование (LOGGING-SPEC §1.9); raw кред-фреймов — только в `.raw`-дампах на VM.
4. creds-папка = приватная зона VM: не пушить, не шарить наружу, права — Administrators only.
5. probe/fork-тесты — только тестовые акки (probeacc*, probetest1-14); реальные креды юзера в тесты не подставлять.
