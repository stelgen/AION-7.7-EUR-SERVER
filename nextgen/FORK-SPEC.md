# 🥷 FORK-SPEC — стандарт внедрения переписей (fork/shadow A/B-атака)

> Обязателен для КАЖДОЙ замены NC-компонента. Дата: 08.10.2026.
> Решение юзера: «fork-proxy ВСЕГДА ставим — наше приложение подсвивает/мимикрирует само для себя, а основные [NC-бинари] отвечают и реально работают. Такой атакой кодим».
> Отработано 3 раза: гейт (fork-proxy 2106→2109), authd (forkauthd 2116 → ориг 2110 + shadow 2117), эволюция в accache R1 (:2220→:2221).

## 1. СУТЬ

Наше приложение **не борется за порт сразу**. Оно ставится **тенью (shadow)** на соседнем порте и получает **копию всего трафика** живого пути. Оригинал продолжает реально работать — юзер не замечает ничего. Мы до полного байт-в-байт паритета, и только потом — свитч. Откат — одна команда, ВСЕГДА.

## 2. ТОПОЛОГИИ (проверенные)

| Схема | Когда применять | Пример |
|---|---|---|
| **Fork-proxy (front + копия)** | наш слушает front-порт (старый адрес), ориг переехал на back-порт; клиентский трафик идёт оригиналу И копируется в наш; наш отвечает только в лог | гейт: fork-proxy 2106 → ориг 2109, копия → наш 2116 (`fork-proxy/`) |
| **Fork-auth (вставка посередине)** | наш сидит МЕЖДУ двумя оригами: front-порт принимает от upstream, релеит в ориг, копию шлёт нашему shadow | authd: gate(2106, authPort=2116) → forkauthd(:2116) → ориг 2110 + копия → shadow(:2117) (`aion-authd/`) |
| **Mirror-копия** | ориг-каталог копируется, порт в его конфиге правится байтово (22206→22207, 2220→2221); mirror-прокси занимает настоящий порт | капча capture (capmirror), accache R1 (ACS :2221) |
| **pktmon (без прокси)** | рестарт компонента дорогой → capture без вмешательства | CacheD64 R1: `pktmon filter port 2006` |

## 3. ПРАВИЛА

| # | Правило |
|---|---|
| 1 | **Ориг — священен**: не слать ему мусор, не рестартить без «го» (L2Authd умирает от кривых пакетов), бекап конфига ДО правки. |
| 2 | **Тень отвечает только в лог** (`N>`), НИКОГДА клиенту, пока не доказан паритет. |
| 3 | **Лог вердиктов**: каждый фрейм = `C>/O>/N>` полный hex + `VERDICT=SAME/DIFF` по ключу (frame,sid,type); N-ONLY/DIFF из-за гонки = арбитраж по позициям в логе, не по ключу. |
| 4 | **Критерии паритета**: все наблюдаемые фреймы/команды — SAME байт-в-байт (динамические значения сравниваются структурно); 0 parse.err/unhandled в логах тени; DB-эффект == ориг (SQL-дифф по времени). |
| 5 | **Свитч только по «го»** юзера, одной операцией, с пронумерованным планом отката (проверенным!). |
| 6 | **Откат всегда готов ДО свитча**: retarget задачи на ориг-bat / старый exe `.bak-<commit>` / возврат портов. |
| 7 | **Тестовые акки**: probe/fork-тесты лочат акки на online-TTL (2–6 мин) — тестовые имена держать пулом (probeacc*, probetest1-14), не логинить реальные. |
| 8 | **Финал**: fork-инфра может остаться навсегда (решение юзера для authd-стенда) — это наблюдательный контур; режимы переключаются конфигом. |

## 4. ИНСТРУМЕНТЫ

| Инструмент | Где | Назначение |
|---|---|---|
| `fork-proxy` (Go, generic) | [fork-proxy/](fork-proxy/) | front→back + копия в наш; лог C>/O>/N> полный hex |
| `forkauthd` (Go) | [aion-authd/](aion-authd/) | эволюция: между gate и ориг + копия в shadow; VERDICT=SAME/DIFF |
| `forkprobe` | `aion-gate/cmd/forkprobe` | синтетический клиент fork-режима (welcome-разбор + AUTH_GG verdict) |
| `probe` | `aion-gate/cmd/probe` | health-check authd (type=3 = healthy) |
| `capmirror`-паттерн | доки капчи/accache | копия ориг-каталога с байтовой правкой порта + mirror-прокси |

## 5. ЧЕК-ЛИСТ ВНЕДРЕНИЯ НОВОЙ ЗАМЕНЫ

1. R1: выбрать схему из §2 (по цене рестарта компонента), поднять fork, юзер логинится ×N → capture.
2. R2–R3: каркас/логика по capture + PDB publics (метод [README §1](README.md)).
3. R4: прогон A/B — VERDICT=SAME по всем наблюдаемым фреймам + SQL-дифф.
4. R5: свитч по «го» с проверенным планом отката; наблюдение 24ч (логины/relogin/ночные циклы).
5. Доки: README компонента (статус/фаза), ROADMAP.md, память.
