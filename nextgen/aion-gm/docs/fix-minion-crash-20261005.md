# Краш-луп клиента при логине: тестовые миньоны (05.10.2026)

> Симптом: после выхода 05:35 каждая попытка входа SteLGeN (char 1002) — клиент падает
> через ~30–45 с после загрузки мира (5 попыток подряд 07:05–07:26, все с сейвом и
> чистым дисконнектом). Сервер полностью здоров: PID с 02:04, мир 16/16, логи молчат.

## Хронология (всё подтверждено)

| Время | Событие |
|---|---|
| 03:09–05:35 | Последняя нормальная сессия (2.5 ч). В 04:12/04:14 созданы 2 миньона (`user_familiar` id 3=980010, id 4=980020, тестовые `testfamiliar_*`). В 05:01–05:17 взяты квест-итемы 182217013/14/15 — они легли в слоты куба 0/1/2 ПОВЕРХ существующих (дубли). |
| 07:05–07:26 | 5 попыток входа → crash-loop. Каждый раз: authd OK → мир OK → ~30 с → клиент умер → Server64 сейвит (`SetLastTransformId` в DBErr). |
| 08:05+ (лок) | Метод исключения: шаг 3 (last_summon_familiar=0) → падение; шаг 1 (куб дубли разведены) → падение; сруб активных квестов → падение; шаг 4 (миньоны удалены, квесты восстановлены, куб откатан как был) → **КЛИЕНТ ЖИВОЙ**. |

## Рут-коз

**Записи тестовых миньонов в `user_familiar`** (980010 `testfamiliar_*`, 980020 `testfamiliar_C1_1`,
источник — KOR-тестовый камень 190200100 `minion_functionstone_kor_01`).
Клиент 7.7 EU не переваривает их ни в пакете списка миньонов, ни при автопризыве
(`last_summon_familiar`) — краш разбора пакета, независимо от автопризыва.

## Что НЕ виновато (проверено методом исключения)

- Дубли слотов куба (0/1/2 по два предмета) — клиенту безразличны. **Но это отдельная
  аномалия данных**: выдача квест-предметов пишет в слот без проверки занятости
  (слоты 0/1/2 были заняты зельями/флаконами/стигма-плашками). Не чинить вслепую.
- Активные квесты (61603/63965/63970 progress=4416/63980/63985) — невиновны (восстановлены — работает).
- Координаты Heiron 210040000 (1047.58/441.13/107.38) — валидны, телепорт не нужен.
- Abnormal-статусы, инстансы, клиентские блобы (settings/quickbar 7168 б) — чисто.

## Применённый фикс (на проде)

```sql
-- 1. Миньоны удалены (бекап: полный .bak AionWorld-20261005-pre-cubefix.bak)
DELETE FROM _AionWorldNew114_rc.dbo.user_familiar WHERE char_id=1002;  -- id 3,4

-- 2. Автопризыв обнулён (сервер успевал вернуть 980020 при crash-логине)
UPDATE _AionWorldNew114_rc.dbo.user_data_ext SET last_summon_familiar=0 WHERE char_id=1002;

-- 3. Квесты восстановлены из построчного бекапа (z_backup_userquest_cubefix, 15 строк)
-- 4. Куб откатан как был: user_item id 195/196/198 → слоты 0/1/2 (z_backup_useritem_cubefix, 48 строк)
```

Откат миньонов (если нужен): `user_familiar` строк нет в построчном бекапе — значения:
`(3, 1002, 980010, 980010, '', 0, 1791162743, 1791174362, 0, 0, 0...,0)` и
`(4, 1002, 980020, 980020, '', 0, 1791162894, 1791174362, 0, 65765, 0...,0)`.

## Правило на будущее

НЕ выдавать миньонов с именами `testfamiliar_*` / камень 190200100
(`minion_functionstone_kor_01`, KOR-тест). Безопасно — только миньоны, которые
есть в клиентских данных EU 7.7. Выдача = `INSERT user_familiar` с валидным
`base_name_id`/`cur_name_id` из `familiars.xml` (или рабочие камни EU).
