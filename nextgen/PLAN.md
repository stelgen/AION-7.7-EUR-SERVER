## 1. ЦЕЛЬ (манифест юзера)

**Переписать ВЕСЬ стек на Go.** Мы владеем сервером до последнего байта и управляем им без ограничений — как владелец, бескомпромиссно. NC-бинари остаются только там, где перепись нецелесообразна (мир-движок Server64+NPCSvr — точечные Ghidra-патчи вместо неё).

- 🔹 **MVP-first**: каждый элемент стека сначала минимально-рабочий (логин/мир живы на каждом шаге), хардинг и красота — потом. «Сейчас идём MVP рабочими по каждому элементу стека, чтобы работало».
- 🔹 **Полное владение**: нет DSN-диалогов, ACP=28591, connStr-реестра, locked exe, «сервер сам решает». Всё конфигурируемо YAML'ом, всё логируется, всё переключаемо.
- 🔹 **Форк-атака как стандарт внедрения** ([FORK-SPEC.md](FORK-SPEC.md)): наше приложение ставится тенью (fork/shadow), мимикрирует под оригинал, а оригинал продолжает реально работать; паритет байт-в-байт (VERDICT=SAME) → свитч → откат одной командой. «Такой атакой кодим».
- 🔹 **op-first**: единый оператор [aion-op](aion-op/README.md) — единственная точка управления стеком (старт/стоп/рестарт/статус/алерты). PowerShell/schtasks напрямую = последний рубеж, только если op не помог.
- 🔹 **Raw-first логирование** ([LOGGING-SPEC.md](LOGGING-SPEC.md)): raw данные на проводе логируются ПЕРВЫМ ходом, логика — вторым; при падении бинарь пишет всё, что может. Цель — всегда видеть, на чём упало.
- 🔹 **Windows → Linux**: оригинальные бинари виндовые, поэтому стек живёт на Windows VM (session 1). Наши Go-бинари кросс-платформенные: сейчас деплой как exe на Windows, позже — нативный Linux-деплой (zram/KSM на Proxmox — потенциально −30–50% RAM).
- 🔹 **Стандарты обязательны**: [TELEMETRY-SPEC](TELEMETRY-SPEC.md) (ship в сеть), [README-TEMPLATE](README-TEMPLATE.md) (доки), [CREDS.md](CREDS.md) (креды в одном месте на VM, не в гите/памяти), [README §4](README.md) (S1–S10).

**Бизнес-суть:** стек = 17 разрозненных NC-чёрных ящиков + SQL-лапша + ручные батники → становится: наши Go-сервисы (конфиги YAML, raw-first логи, ship-телеметрия) + op-оператор (одна панель) + ориг-пара мира + SQL как холодное хранилище.

| Креды/секреты | Единая папка на VM `D:\SAION\creds\`; в гит/память/чаты — никогда |

### Отвязка от MSSQL/ODBC
- **Ступень 1 (замены 1–6):** свои сервисы говорят с SQL напрямую по TDS (go-mssqldb) — ODBC/DSN/ACP-ритуалы исчезают; MSSQL остаётся СУБД.
- **Ступень 2:** auth-слой прост → PostgreSQL/SQLite реален; мир (13.8 ГБ) — позже; наш RAM-кэш (accache/cache) делает SQL «холодным».
- **Ступень 3:** NC остаётся только парой Server64+NPCSvr как «мир-движок», всё вокруг — наше.

- ✅ Доки взрослеют: каждый nextgen-проект ведёт README по шаблону, статусы/проценты/блокеры/артефакты синхронны с кодом и памятью.
