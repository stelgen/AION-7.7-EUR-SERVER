## 1. ЦЕЛЬ (постановка юзера)

**Один бинарь** (Go, статический), который:
- 🔹 многопоточный (горутины), **без утечек памяти**, детерминированный GC-профиль, живёт месяцами;
- 🔹 **коннектится к текущему стеку** и обслуживает его, ничего не ломая (adaptive: stack жив как есть);
- 🔹 даёт **вкладки по сервисам** — управляемость, которой нет у 17 разрозненных NC-приложений;
- 🔹 **бизнес + технический мониторинг** в одном месте;
- 🔹 работает как **лаунчер** (порядок старта/стопа, watchdog, парные рестарты NPC+MAIN);
- 🔹 будущность: **без трипанемы MSSQL/ODBC** (DSN-диалоги, ACP=28591, connStr-реестр, max text repl size — всё это болезнь NC-бинарей) → «делаем максимум свой сервер».

**Бизнес-суть:** сейчас стек = чёрные ящики + SQL-лапша + ручные батники. Наш бинарь = мозг и панель управления. Замена NC-компонент — поэтапная, с сохранением работоспособности на каждом шаге.

## 3. ТРЕК A — «ОПЕРАТОР» (первый результат, недели)

Единый Go-бинарь `aion-op` (порт web-UI ~10200, SQLite-эмбед для метрик/событий).

### Модули
1. **Supervisor**: порядок старта LOG→CACHE→NPC→MAIN (и лёгкие ONSTART), port-wait циклы вместо sleep, дедуп процессов, парные рестарты NPCSvr+Server64 (смерть одного ⇒ graceful второго).
2. **Watchdog**: чек-порты (2104/2106/2107/2051/2220/2005/2006/2007/2002/7777/22206/10057), ожидание «16 ESTABLISHED на 2002» = мир собран, авто-рестарт по правилам юзера, кнопка «kick и перезапуск» .
3. **Log-тейлер + парсер**: `CacheServer\log\*.err` (2812, Too slow, DeadLock Detected, Strings DB unexpted id), `MainServer\log\*.err` (AboutToPlayerTimer, Shutdown By NpcSocket), authd `winlog/packet/dual`, NPCSvr err → события в дашборд.
4. **Тех-метрики**: RAM/потоки/хендлы процессов (⚠ динамика хендлов Server64 827k — кандидат утечки), FreeCommit/FreePhys, SQL: waits, plan cache, CatchBlocked XE, CCU (user_count), TBL_GAME_SERVER_INFO/WORLD_INFO (aiongm_ur).
5. **Бизнес-метрики**: логины/час (authd), краши/сутки, uptime пары, «кто онлайн» (char_id/аккаунт), версии патчей XML/бин (MD5-инвентарь).
6. **Алерты**: хендлы/RAM-порог, новый 2812, Super-Lag, RESOURCE_SEMAPHORE очередь, смерть любого компонента.
7. **Вкладки** (web-UI): Overview / Auth / Cache / NPC+World / LogServer / SQL / Логи / Рестарты / Настройки.
8. **Прокладки-MITM** (опция): multi-port снифферы 2106/2002/2006 — наблюдение трафика (по образцу aionproxy.py), без правки.

### Реализация
- Go 1.2x (тулчейн уже в `~/STELGEN/go-dist`); UI: embedded HTML (нет зависимостей) или TUI bubbletea;
- доступ к Windows VM: **Phase 0** — SSH/WinRM read-only (как сейчас); **Phase 1** — мини-агент-сервис на VM (Go, ~2 МБ, единственный компонент который мы УСТАНАВЛИВАЕМ на прод — по «го»);
- память: streaming-метрики в SQLite (WAL), retention 30 дней;
- без утечек: pprof-эндпоинт, лимиты горутин на вкладку, контекстные таймауты.

### Отвязка от MSSQL/ODBC (юзерская цель)
- Ступень 1 (с заменой 3–5): свои сервисы говорят с SQL Server напрямую по TDS (go-mssqldb) — **ODBC/DSN/ACP/диалоги исчезают полностью**, MSSQL остаётся как СУБД (данные целы).
- Ступень 2 (после 6–8): схема auth-слоя простая → перенос в **PostgreSQL/SQLite** реален; мир (user_data/user_item 13.8 ГБ) — позже; CacheD → наш RAM-кэш делает SQL «холодным» хранилищем.
- Ступень 3: максимум свой сервер = NC остаётся только парой Server64+NPCSvr (+ScriptDLL) как «мир-движок», всё вокруг — наше.

## 5. LINUX-СТРАТЕГИЯ (юзер: «может под линукс даже лучше»)

| Вариант | Что даёт | Риск/цена |
|---|---|---|
| **V1 (рекомендую старт)**: оператор живёт на Linux (Proxmox-хост/LXC), управляет Windows VM по SSH/WinRM; zswap/zram/KSM на хосте | немедленный старт; **KSM может дедуплицировать одинаковые страницы карт NPCSvr/Server64 — потенциально −30–50% RAM хоста**; zswap смягчает swap-штормы | Zero-риск для прод-софта (тюнинг гипервизора) |
| **V2**: Windows VM остаётся единственной NC-платформой, наш оператор-бинарь внутри VM (Phase 1 агент) | локальный доступ к процессам/логам без сети | агент = единственная инсталляция на прод |
| **V3 (финал)**: все СВОИ сервисы — Linux-нативные (Go кросс-платформа), Windows VM только для пары Server64+NPCSvr | минимум Windows; стек почти весь наш | доступно после Трека B ступени 2–3; NC-мир на Linux не портируется (wine+NC-guard = нет) |

⚠️ Гибрид навсегда: полная Linux-нативность ВСЕГО мира нереальна (NC-бинари) — реалистичная цель = «Windows-VM для мира, всё остальное — наше и кросс-платформенное».
