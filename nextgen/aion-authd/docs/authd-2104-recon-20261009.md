# R0-2104: разведка роли порта 2104 (Server64-канал) — 09.10

> Статус: R0-частичная ✅ (артефакты собраны, семантика подтверждена Encom-эталоном).
> Глубокий дизasm dispatch 2104 — следующая сессия (заготовки ниже готовы).

## 1. Эталон семантики 2104 (Encom leak 7.5-7.7, `reference/encom-leak-7577/Login Server`)

Канал **gameserver** (GS↔LS = наш 2104: Server64 → L2Authd):

- **GS→LS** (clientpackets/gameserver): `CM_GS_AUTH` (регистрация GS), `CM_ACCOUNT_AUTH`,
  `CM_ACCOUNT_DISCONNECTED`, `CM_ACCOUNT_LIST`, `CM_ACCOUNT_RECONNECT_KEY`, `CM_ACCOUNT_TOLL_INFO`,
  `CM_GS_CHARACTER`, `CM_GS_PONG`, `CM_BAN`, `CM_LS_CONTROL`, `CM_MAC`, `CM_MACBAN_CONTROL`,
  `CM_PREMIUM_CONTROL`, `CM_PTRANSFER_CONTROL`
- **LS→GS** (serverpackets/gameserver): `SM_GS_AUTH_RESPONSE`, `SM_ACCOUNT_AUTH_RESPONSE`,
  `SM_ACCOUNT_RECONNECT_KEY`, `SM_GS_CHARACTER_RESPONSE`, `SM_LS_CONTROL_RESPONSE`, `SM_PING`,
  `SM_REQUEST_KICK_ACCOUNT`, `SM_BAN_RESPONSE`, `SM_PREMIUM_RESPONSE`, `SM_PTRANSFER_RESPONSE`, `SM_MACBAN_LIST`

Канал **aion-клиента** (наш 2110 через AuthGateD) — точное совпадение с нашей картой wire:
`CM_AUTH_GG, CM_LOGIN, CM_PLAY, CM_SERVER_LIST, CM_UPDATE_SESSION` (opcodes 0x00/01/03/04/06/07/0b/0c).

**Вывод:** 2104 = gameserver-канал: регистрация мира, relay авторизаций аккаунтов в мир,
reconnect-key, kick аккаунта, toll/premium, character-count для serverlist. Без него свитч
2110 на наш authd отрежет Server64 от authd → мир деградирует (блокер R6 подтверждён семантически).

## 3. ✅ ПРОТОКОЛ-КОРЕНЬ СНЯТ ЖИВЫМ PACKET-ЛОГОМ (09.10, дизasm НЕ нужен — решение юзера)

Решение юзера: 2104-канал = «просто живой» — приоритет пониманию протокола, дизasm только по остатку.
L2Authd сам пишет ПОЛНЫЙ текстовый wire-дамп: `D:\AION_LIVE_SERVER\AuthD\etc\log\*.packet`
(корпус: `../authd-ref/logs-2104/` — пойман живой логин юзера 09:32:56 + вход в мир 09:33:22).
Формат строки: `Дата,Направление(сессия),ТИП,HEX[END]`. Полезная нагрузка 2104 начинается с `uid` u32 LE (`f2030000` = 1010).

**Словарь 2104 Auth<->World (сессия мира, одна на Server64):**

| Тип | Напр. | Payload | Смысл |
|---|---|---|---|
| 2 | A→W | пусто | heartbeat authd, каждые 60с |
| 5 | W→A | `0000f401` (реже `0100f401` — байт0 0→1 при логине юзера) | pong/статус мира |
| 0 | A→W | uid + «Stelgen» + pad + `d0070000`(=2000) + `3030…30` + `554da0b8` + 24×`ff` + 2×`50c2366b` | релей логина: аккаунт онлайн |
| 0 | W→A | uid + `02000000` | ack мира |
| 38/27/25/24/39/40 | W→A | `00`+uid / uid | события мира (вход чара, uid-пинги) |
| 2 | W→A | uid + 10×`00` | событие мира |
| 35 | W→A | uid + `01` + char_id(`ea030000`=1002) + lev(`50`=80!) + `b2e7c56a` | инфо о чаре (uid, char, level) |
| 3 | W→A | uid + `0000` + `6a000000` + char_id + lev | инфо о чаре #2 |
| 19/16/44/14/13/31 | A→W | uid (+00/`01010001`/`63…`) | квитанции authd |

**MVP-вывод:** 2104 = тонкий канал: heartbeat 60с + релей «аккаунт онлайн» (type 0) + uid-эхо.
Бизнес-логики НЕТ. Нашему authd достаточно: принять Server64, heartbeat type 2/5, слать type 0
при завершении логина на 2110, отвечать uid-квитанциями. Дизasm НЕ требуется; сверка — по живому
packet-логу (он же регрессионный корпус). При смерти authd мир сам реконнектится
(`AuthSocket Close` → `Connected to AuthServer` — факт из aion-op/authlog-merge-0410.md).

**Бонус из того же лога:** каноны 2110 подтверждены ОРИГОМ ЕЩЁ РАЗ (Auth->Gate type 3 = 52Б с
token/2000/unk1; type 4 = `[010101][c0a8007d][611e]…`; type 7 = `[pk1=1][uid][serverID=1]`);
виден PA-обмен (Auth↔PAServer type 1, 168Б с «stelgen») и внутренние шаги authd
(`FindAccount` → `InitLoginUserData` → `AgeCheck`/`CheckAge`/`CheckGMUser` → `IPServer off`, все «OK»).

Артефакты: `../authd-ref/logs-2104/*.txt` (золотой корпус), `../authd-ref/pdb-publics-4513.txt`, `procs-aionaccounts-77.rpt` (БД).
След. шаг: реализовать 2104-листенер в нашем authd по корпусу (pktmon не нужен — L2Authd логирует всё сам).
