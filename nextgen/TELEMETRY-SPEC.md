## 1. БИЗНЕС-ПРАВИЛА (требование к Треку B)

| # | Правило |
|---|---------|
| 1 | **Ноль мусора на диске.** Свой сервис пишет на диск ТОЛЬКО: (а) свой конфиг, (б) запущенный exe. Логи/метрики/дампы — В СЕТЬ, единым потоком, единым форматом. Исключение — локальный ndjson-фолбэк, включаемый ТОЛЬКО явно в конфиге (`ship.file.enabled`). |
| 2 | **Один стак.** Все переписи шлют телеметрию одним и тем же механизмом (`internal/ship`), приёмник — один на Linux (rsyslog/Vector → Loki/Grafana). Не плодить своихsink'ов на сервис. |
| 3 | **Ship ≠ критичный путь.** Недоступный приёмник, «не настроен коннектор», сеть лежит — сервис НЕ ПАДАЕТ, НЕ ТОРМОЗИТ, НЕ КОПИТ бесконечно: очередь с дроп-политикой + счётчики. |
| 4 | **Сам-статус.** Сервис высылает своё состояние действий: что поднял (коннекты, порты), что распарсил, что отдал в БД, что отбросил — `ev=self` каждые 5 мин + события действий в реальном времени. |
| 5 | **Raw и ошибки — наружу.** Всё, что не распарсилось/не покрыто, уходит с событием ошибки + cap'нутым raw-хексом. Полные дампы — только в опциональный локальный capture (временно, до закрытия layout'а). |
| 6 | **Конфиг одинаковый.** Ключи `ship.*` идентичны во всех сервисах (см. §5). Секретов в конфиге нет. |

## 2. ТРАНСПОРТ (выбор и дефолты)

| Транспорт | Когда | Формат wire |
|---|---|---|
| **syslog RFC5424 UDP** (дефолт) | прод-стек, приёмник в локалке | `<PRI>1 <ts> <host> <app> <procid> <msgid> - - {JSON}`; 1 событие = 1 датаграмма ≤1400 Б (перелив — обрезка payload, шапка цела); fire-and-forget = ничего не блокирует |
| **syslog RFC5424 TCP** | нужен надёжный канал | octet-counted framing RFC6587: `LEN <PRI>1 ...`; персистентный коннект, реконнект при ошибке |
| **HTTP ndjson** | современный коллектор (Vector HTTP source, будущий Loki push) | POST `application/x-ndjson`, 1 JSON-строка + `\n`, timeout 3с, 5xx = недоставлено |
| **файл ndjson** | только `ship.file.enabled: true` | `<dir>/YYYY-MM-DD.ndjson`, append |

Приёмник на Linux (потом, готовое стандартное решение — НЕ самописное):
- **rsyslog** — есть в каждом дистре: UDP/TCP 514, RFC5424 нативно; дальше хоть в файлы, хоть forward в Loki/Elastic.
- **Vector** (vector.dev) — тот же вход + маршрутизация в **Loki/Grafana** — красивый web-вьюер и запросы.
Рекомендация: rsyslog на приёме → Loki → Grafana. Канал не трогаем.

## 3. ФОРМАТ СОБЫТИЯ (JSON, стабильный контракт приёмника)

```json
{
  "ev":  "text",                  // тип события, см. §4
  "svc": "svc3",                  // сервис/подсистема источника (наше имя)
  "remote": "127.0.0.1:55316",   // удалённая сторона (для коннект-событий)
  "msg":  "tlog id=928 n=2 [1002:\"SteLGeN\"]...",  // человекочитаемая строка
  "err":  "records: body=190, want 194",            // текст ошибки (если есть)
  "raw":  "DF 00 09 BA F6 A0 03 ...",               // capнутый raw-хекс (max_raw, default 512)
  "data": { "world": 210040000, "n": 2, "stamp": "2026-10-05 11:59:00.350" } // структурика
}
```
RFC5424: PRI = facility<<3 | severity; severity: 3 (err) = `parse.err`/`db.err`, 4 (notice) = `self`/`stop`, 6 (info) = остальное. MSGID = ev. Host = hostname источника. App = имя сервиса (у logd — `aion-logd`; у следующих переписей — своё).

## 4. СОБЫТИЯ (словарь ev)

| ev | Смысл | Кто шлёт |
|---|---|---|
| `start` / `stop` | подъём/остановка сервиса + конфиг-сводка (порты, флаги) | все |
| `conn.up` / `conn.down` | коннект поднят/закрыт: remote, порт, handshake, счётчики сессии | все с коннектами |
| `version` | результат handshake (builder/min клиента) | logd |
| `server.started` | NC-пакет ServerStarted (svc, id, x) | logd |
| `status` | распарсенная телеметрия type-5 (svc, world, x/y/z, metrics, engine_ms) | logd |
| `text` | распарсенный текст-лог type-9 (id, entries/онлайн, world, stamp) | logd |
| `parse.err` | не покрыто парсером: err + raw (полный дамп параллельно в .raw) | logd |
| `db` / `db.err` | действие в БД (freedisk/serverstatus/InitializeCount/...) или ошибка | все с БД |
| `sweep` | чистка локальных файлов (retention): сколько удалено | все с файлами |
| `self` | **сам-статус**: uptime, sent/dropped, ошибки по синкам, очередь | все |

## 5. КОНФИГ (идентичен во всех переписях)

```yaml
ship:
  enabled: false        # мастер сетевых синков; false = сервис живёт как раньше
  syslog: { net: "udp", host: "", facility: 1 }   # udp|tcp, host:port
  http:   { url: "", timeout: 3 }
  file:   { enabled: false, dir: "./logs/ship" }  # фолбэк — ТОЛЬКО явно
  queue: 4096           # буфер очереди; переполнение = drop + счётчик
  self_sec: 300         # период ev=self
  max_raw: 512          # кап raw-хекса в событии
```

## 6. МЕХАНИКА НЕПАДАНИЯ (реализация-эталон, internal/ship)

- `Send()` — только неблокирующая постановка в chan; переполнение → `dropped++` (никогда не ждать).
- `Run()` — один потребитель; каждая отправка в `recover()`; ошибка синка → счётчик, next-попытка при следующем событии (self-тикер даёт регулярный ретрай).
- UDP: dial+write с deadline 2с, датаграмма ≤1400 Б. TCP: персистентный коннект, при ошибке Close+nil → реконнект на следующем событии. HTTP: `http.Client` timeout.
- При `ctx.Done` — drain 300 мс и закрытие синков; финальный `stop`-эвент со счётчиками.
- nil-безопасность: `ship.S == nil` (или `enabled=false` и `file=false`) → `Send()` = no-op, стоимость — один if.

## 7. ЧТО ЭТО ДАЁТ ТРЕКУ B

Каждая следующая перепись (CAPTCHA → AuthGateD → ...) наследует: готовый пакет `internal/ship` (копирование, ~0 затрат), готовый приёмник на Linux (rsyslog), единый дашборд в Grafana по всем сервисам сразу (`{app="aion-captcha"} | json`), и полное отсутствие файлового мусора от наших сервисов. NC-оригиналы при этом продолжают писать свои файлы — их тейлеры aion-op не трогаем.
