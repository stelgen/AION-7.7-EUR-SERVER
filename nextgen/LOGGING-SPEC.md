# 📜 LOGGING-SPEC — стандарт логирования СВОИХ сервисов (raw-first)

> Обязателен для КАЖДОЙ переписи (наряду с [TELEMETRY-SPEC.md](TELEMETRY-SPEC.md)).
> Дата: 08.10.2026. Решение юзера: «сначала логирование всегда raw, потом логика — чтобы видеть, на чём упали».
> Эталон реализации: `aion-logd/internal/writer` (per-day файлы + `WriteRaw` hexdump) + ship-события `parse.err` с capнутым raw.

## 1. ПРАВИЛА

| # | Правило |
|---|---|
| 1 | **Raw ПЕРВЫЙ ход.** Любой входящий/исходящий байтовый поток пишется в лог КАК ЕСТЬ (hexdump) ДО попытки парсинга. Логика/интерпретация — вторым ходом, отдельной строкой рядом. Никогда не «успешно распарсили и не логнули raw». |
| 2 | **При падении — писать ВСЁ, что может.** Паника/фатальная ошибка/неизвестное состояние = перед смертью вылить в лог максимум контекста: последний raw, состояние (конфиг-сводка, счётчики, текущая сессия), стек ошибки. Panic-recovery → запись → опциональный рестарт. |
| 3 | **Два файла-направления:** (а) `logs\io\<YYYY-MM-DD>.tN.hex` — сырой трафик rx/tx с таймстампами; (б) смысловой лог (`logs\<svc>.log`, а также `.err`-формат оригинала если на нём завязаны тейлеры op). Формат строки: `ts LEVEL tag msg raw=...`. |
| 4 | **Не покрыто парсером = `parse.err`**: ship-событие с err + capнутым raw (max 512Б) + полный дамп в `.raw`-файл. Никаких молчаливых съеданий байтов (урок logd-итераций 1–2). |
| 5 | **Fork-логи (A/B):** `C>` клиент, `O>` оригинал, `N>` наш — полный hex каждого фрейма + вердикт SAME/DIFF; вердикт-арбитраж по позициям в логе (гонка тени ≠ баг). См. [FORK-SPEC.md](FORK-SPEC.md). |
| 6 | **Логи не растут гигантами бесконечно:** per-day файлы + retention (`retention_days`, default 14) чисткой при старте и раз в 30 мин. |
| 7 | **Ship дублирует критичное наружу** по [TELEMETRY-SPEC.md](TELEMETRY-SPEC.md): `parse.err`/`db.err`/фейлы — severity 3 (err); raw в событии — capнутый. |
| 8 | **Баннер старта** = канарейка: версия (коммит), режим, порты, ключевые конфиг-значения (rsa_exponent и пр.). По баннеру проверяется, что конфиг прочитан (пустой конфиг/дефолты = немедленный откат). |
| 9 | **Секреты в логах запрещены:** пароли/connStr/токены маскируются. Raw кред-фреймов гейт-уровня допускается только в `.raw`-дампах на VM (не в ship/гит). |

## 2. КУДА ПИСАТЬ

| Что | Где |
|---|---|
| Боевые логи сервиса | `D:\SAION\<svc>\logs\` (+ stdout→`<svc>.log` через run.cmd `>> ... 2>&1` — редирект ОБЯЗАТЕЛЕН: паники видно) |
| Raw io-дампы | `D:\SAION\<svc>\logs\io\` (per-day `.tN.hex`, rx/tx помечены) |
| Fork A/B | `D:\SAION\<svc>\fork-*.log` (формат §1.5) |
| Наружу (телеметрия) | ship → rsyslog/Loki ([TELEMETRY-SPEC.md](TELEMETRY-SPEC.md)) |
| .err ориг-сервисов | НЕ трогаем — их тейлерит op (наш logd пишет .err-формат, если тейлеры завязаны) |

## 3. ЧЕК-ЛИСТ НОВОГО СЕРВИСА
