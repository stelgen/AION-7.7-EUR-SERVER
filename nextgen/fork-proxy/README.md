# fork-proxy — generic TCP fork/shadow-прокси (инструмент A/B-атаки)

> Прародитель метода [FORK-SPEC](../FORK-SPEC.md). Первый форк: гейт 2106 → ориг 2109, копия клиентского трафика → наш aion-gate (2116).
> Эволюция с той же идеей: `forkauthd` в [aion-authd/](../aion-authd/) (2116 → ориг 2110 + копия в shadow 2117, VERDICT-сверка).
> Статус: ✅ используется; компилируется под windows/linux (`GOOS=windows GOARCH=amd64 go build -o fork-proxy.exe .`).

## Что делает

```
клиент ──C>── fork-proxy ──→ ОРИГИНАЛ (back-порт, живой путь, ответы идут клиенту)
                 └── копия C-трафика ──→ НАШЕ приложение (тень) + лог всех направлений
```

- Клиентский трафик (`C>`) идёт оригиналу И копируется в наш бинарь (наш слушает/мимикрирует для себя, ничего юзеру не отвечая).
- Ответы оригинала (`O>`) идут клиенту (реальная работа = у оригинала).
- Ответы нашего (`N>`) — ТОЛЬКО в лог. Никакой конкуренции за порт.
- Лог: `C> len=N hex=…` / `O> …` / `N> …` — полный hex каждого чанка (raw-first, [LOGGING-SPEC](../LOGGING-SPEC.md) §1.5).

## Использование

```bash
fork-proxy -front :2106 -back 127.0.0.1:2109 -shadow 127.0.0.1:2116 -log fork.log
```

Порты задаются флагами (см. main.go). На VM запускать ТОЛЬКО задачей планировщика ([FORK-SPEC §3](../FORK-SPEC.md) — не Start-Process из ssh).

## Варианты схемы

| Схема | Применение | Инструмент |
|---|---|---|
| Fork-proxy front+копия | проверка нового бинаря на живом трафике без отрыва порта | этот exe |
| Fork-auth (вставка) | подслушать канал между двумя оригами | `forkauthd` (aion-authd) |
| Mirror-копия ориг-каталога | ориг сам слушает соседний порт (правка конфига байтово), прокси занимает настоящий | `capmirror`-паттерн (капча/accache R1) |
| pktmon без прокси | рестарт дорогой (CacheD64/Server64) | `pktmon filter port` на VM |

## Правила (кратко; полные = FORK-SPEC)

1. Ориг — священен: бекап конфига до правки, никакого мусора в его сторону.
2. Тень отвечает только в лог до доказанного байт-в-байт паритета.
3. Вердикт SAME/DIFF по ключу (frame,sid,type); гонка тени ≠ баг — арбитраж по позициям в логе.
4. Свитч/откат — только по «го», откат = одна проверенная команда.
