## 2. ЗАПУСК ЧАТА (обязательный порядок, ~5 минут)

1. **Чтение**: память `STELGEN/projects/aion_server_2026-10-02` (+ страница компонента, если есть) → [README.md](README.md) (стек-таблица) → README компонента → его ROADMAP → его PROMPT. Готово = контекст восстановлен.
2. **Первое сообщение = «ГДЕ МЫ»** (блок пульса, §3): статус, фаза, последний коммит, следующий шаг, блокеры. Без «разрешите объяснить» — сразу пульс и за работу.
3. **Работа**: по следующему шагу ROADMAP/PROMPT компонента. Не по шаблону «спроси что делать» — план уже лежит в доках.
4. **Блокер** → 1) вариант обхода (сорс-эталон → дизasm → capture → конфиг), 2) фикс обхода в ROADMAP, 3) только если хода нет физически — вопрос юзеру (с 2–3 вариантами и своим выбором).
5. **Незнакомый компонент** (нет папки) → создать по шаблону (README + ROADMAP + PROMPT), страницу памяти, строчку в реестр §1 — потом работать.
6. **Симметрия-контракт** (проверять в конце каждого чата): (а) у КАЖДОГО компонента есть страница памяти `STELGEN/projects/aion_server_2026-10-02/<имя>` — при первом касании создать заглушку; (б) в папке компонента self-contained: README + ROADMAP (или SNAPSHOT/архитектура-док) + PROMPT (+RESEARCH где есть, +docs/); (в) в корне nextgen — ТОЛЬКО сквозные спеки/планы/манифесты; (г) архивные промпты лежат в папке своего компонента (docs/PROMPT-*.md / PROMPT-ARCHIVE.md), НЕ в корне; (д) ссылки после переносов проверяются скриптом битых линков — 0 битых перед пушем.

## 3. ПУЛЬС КАЖДОГО СООБЩЕНИЯ (контекст не теряется)

**Каждое** сообщение агента заканчивается блоком:

```
📊 ПУЛЬС [aion-ic R1] 08.10 03:45
✅ сделано: ...
⏭️ следующее: ...
🚧 блокеры: ...
📦 коммит: <hash> (pushed) | артефакты: <пути>
```

- Событие, изменившее картину (факт/решение/теория/статус) — фиксируется **В ДОКИ СРАЗУ**, не «в конце чата»: дельта в README/ROADMAP компонента + коммит + пуш. Чат может умереть в любой момент — состояние обязано восстанавливаться из гита+памяти в любую секунду.
- В конце чата: финальный пульс + память-дельта (что сделано/где лежит/следующий шаг/новые креды-указатели) + синхронизация nextgen/README (статусы/%) — правило юзера «пульс не теряется».

## 4. ТЕОРИИ: фиксация на момент + чистка лжи

| Правило | Суть |
|---|---|
| **Гипотеза фиксируется** | В ROADMAP компонента — секция «🧪 Журнал теорий»: дата, формулировка, способ проверки, статус (⏳/✅/❌). Теория без способа проверки не живёт. |
| **Проверка = канон или отхлоп** | Подтверждено → перенос в канон README («live-доказано», источник: capture/дизasm/сорс). Опровергнуто → **удалено из канона СРАЗУ**, остаётся строка в леджере решений (что думали → почему нет → чем доказали). |
| **«Исправил = удалил»** | Устаревшее/неверное утверждение удаляется из ВСЕХ доках в тот же коммит (README, ROADMAP, PROMPT, снапшоты). Не «пометим потом» — юзер чат прочитал и ложь пошла в новый чат. Память задним числом НЕ переписывается: новая дельта-запись помечает исправление. |
| **Динамические факты датированы** | Статусы (PID, порты-состояние, «сейчас на проде») — всегда с датой; статика без даты = подозрение на мусор. |
| **Взгляд назад запрещён** | «Эталоны/опенсорс ≠ live» — арбитр всегда живой трафик/файл ориг (урок гейта, леджер №12). |

## 5. САМООРГАНИЗАЦИЯ (агент двигает сам)

- **Цель-максимум: ФУЛЛ-СЕРВЕР БЕСКОМПРОМИССНО** — переписываем ВСЕ компоненты стека на Go; «деприоритизировано» ≠ «отменено» (мир npc/main, relay, ranking, gm, .NET-мелочь — в плане, просто позже). Каждое рабочее состояние = логин и мир живы (MVP-first: сначала работает, потом красиво).
- **Порядок источников (СУРСЫ-ПРИОРИТЕТ, перед дизасмом!)**: 1) собрать ВСЕ чужие сурсы/артефакты/эталоны/эмуляторы — даже старых версий (киты 2.7/4.6/5.8, декомпилы, Java-эмуляторы, форумы) → 2) **мимикрия-first**: тень/форк повторяет чужой проверенный опыт → 3) свой дизасм/capture — ТОЛЬКО когда всё пройденное до нас исчерпано. Потом — cycle: op-first (всё через op) → fork-тень ([FORK-SPEC](FORK-SPEC.md)) → capture → код MVP → A/B → свитч по «го» → наблюдение.
- **КРОСС-ПУЛЬС ШАРИНГ (обязателен)**: компоненты коммуницируют — протоколы/хидеры/процедуры/дизасм у NC-бинарей ОБЩИЕ (Shared-код). Нашёл открытие, касающееся СОСЕДА (authd↔gate, main↔npc↔cache, ic↔main) → зафиксируй его В ПУЛЬСЕ СОСЕДА тоже (его README-канон/ROADMAP-теорий + «📊 сосед узнал:» строка в его странице памяти/доке) — чтобы заново не ходить кругами по уже посчитанному однажды.
- **Своя строка в мастер-таблицах**: каждый чат обновляет СВОЮ строку в стек-таблице [README.md](README.md) §2 и (при статус-сдвиге) в [../README.md](../README.md) — синхронно с README своего компонента.
- **Сам решай**: порядок фаз, инструмент capture, структуру кода, тест-сценарии, что чинить первым. **Не решай сам**: прод-действия (свитч/рестарты ориг-компонентов/бекапы с потерей данных) — только по «го»; бизнес-выборы (какие фичи нужны юзеру).
- **Роадмап двигается агентом**: фазы добавляются/переоткрываются с датами, % пересчитывается по фазам, старые строки заменяются (не копятся).
- **Мусор**: тестовые акки/temp-файлы помечать на удаление в ROADMAP, не копить.
